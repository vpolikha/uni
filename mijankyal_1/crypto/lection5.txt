### CRYPTOLOGY CHEATSHEET — RC4 (Rivest Cipher 4)

RC4 is a symmetric stream cipher developed by Ron Rivest in 1987.

Unlike AES, which is a block cipher, RC4 encrypts data byte by byte using a pseudorandom keystream.

Broken — insecure and deprecated

RC4 is important historically and educationally, but it must not be used in modern applications.

### 1\. Basic concept

RC4 uses:

* A secret key of variable length.

* An internal state consisting of a permutation of 256 bytes.

* A pseudorandom number generation algorithm (PRGA) to produce a keystream.

Encryption and decryption both use XOR:

C_i=P_i\\oplus K_iP_i=C_i\\oplus K_i

Where:

* — plaintext byte.

* — ciphertext byte.

* — keystream byte.

Important: RC4 is a stream cipher, so it does not divide the message into fixed-size blocks.

### 2\. Key generation

The user supplies a secret key.

The key can have a variable length, traditionally between 1 and 256 bytes.

The key is used to initialize an internal array called `S`.

The array contains all integers from 0 to 255 in a permuted order.

Initially:

```text
S[0] = 0
S[1] = 1
S[2] = 2
...
S[255] = 255
```

The Key Scheduling Algorithm (KSA) shuffles this array according to the secret key.

### 3\. Key Scheduling Algorithm (KSA)

Purpose: Initialize and shuffle the internal state array `S` using the secret key.

Algorithm:

```text
1. Initialize S:

   for i = 0 to 255:
       S[i] = i

2. Initialize j = 0

3. Shuffle S:

   for i = 0 to 255:
       j = (j + S[i] + key[i mod key_length]) mod 256

       swap(S[i], S[j])
```

After KSA, `S` is a permutation of numbers from 0 to 255.

Important:

* KSA is executed once for each new key/stream.

* It does not encrypt the plaintext.

* It prepares the internal state for keystream generation.

### 4\. Pseudo-Random Generation Algorithm (PRGA)

Purpose: Generate pseudorandom bytes called the keystream.

Initialize:

```text
i = 0
j = 0
```

For every output byte:

```text
1. i = (i + 1) mod 256

2. j = (j + S[i]) mod 256

3. swap(S[i], S[j])

4. t = (S[i] + S[j]) mod 256

5. K = S[t]
```

The resulting `K` is one byte of the keystream.

Repeat these steps to generate as many bytes as necessary.

Important: The internal state changes after every generated byte.

### 5\. Encryption algorithm

Once the keystream is generated, encryption is straightforward.

For every plaintext byte:

C_i=P_i\\oplus K_i

Example:

```text
Plaintext:  01010101
Keystream:  10101010
            --------
Ciphertext: 11111111
```

The sender transmits the ciphertext to the receiver.

### 6\. Decryption algorithm

Decryption uses exactly the same XOR operation.

The receiver must:

* Possess the same secret key.

* Initialize RC4 using KSA.

* Generate the same keystream using PRGA.

* XOR the ciphertext with the keystream.

P_i=C_i\\oplus K_i

Example:

```text
Ciphertext: 11111111
Keystream:  10101010
            --------
Plaintext:  01010101
```

Important: Encryption and decryption use the same algorithm because XOR is reversible.

### 7\. Complete RC4 structure

Secret key

KSA — Key Scheduling Algorithm

Initializes and shuffles S\[0...255\]

PRGA — Pseudo-Random Generation Algorithm

Generates keystream bytes

XOR with plaintext

Ciphertext = Plaintext XOR Keystream

### 8\. Weaknesses and vulnerabilities

RC4 has several serious security weaknesses.

1\. Statistical biases

The generated keystream is not perfectly random. Certain output bytes have statistical biases, especially near the beginning of the stream.

2\. Weaknesses in KSA

The key scheduling process has weaknesses that can leak information about the secret key.

3\. Related-key attacks

In protocols that use poorly designed RC4 key construction, attackers can exploit relationships between different keys.

A famous example is the attack against WEP wireless encryption.

4\. Initial keystream weaknesses

The first bytes of the RC4 keystream are particularly biased. Some older implementations discarded the first bytes to reduce certain weaknesses, but this did not make RC4 secure.

5\. No authentication

RC4 only provides encryption. It does not inherently provide integrity or authentication.

### 9\. Applications and historical use

RC4 was historically used in:

* WEP wireless security.

* WPA-TKIP (legacy Wi-Fi security).

* SSL/TLS (older versions).

* Microsoft implementations and older protocols.

It has since been prohibited or deprecated in modern security protocols because of its vulnerabilities.

Modern alternatives include:

* ChaCha20.

* AES-CTR.

* AES-GCM (provides encryption and authentication).

### 10\. Exam summary

```text
============================================================
RC4 — RIVEST CIPHER 4
============================================================

TYPE:
    Symmetric stream cipher.

KEY:
    Variable-length secret key (traditionally 1–256 bytes).

INTERNAL STATE:
    S[256] — permutation of integers from 0 to 255.

ALGORITHM HAS TWO MAIN STAGES:

1. KSA — Key Scheduling Algorithm

    Purpose:
        Initialize and shuffle the state array S.

    Steps:
        Initialize S[i] = i.
        Initialize j = 0.

        For i = 0 to 255:
            j = (j + S[i] + key[i mod key_length]) mod 256
            swap(S[i], S[j])

2. PRGA — Pseudo-Random Generation Algorithm

    Purpose:
        Generate pseudorandom keystream bytes.

    Initialize:
        i = 0
        j = 0

    For each byte:
        i = (i + 1) mod 256
        j = (j + S[i]) mod 256
        swap(S[i], S[j])
        t = (S[i] + S[j]) mod 256
        K = S[t]

ENCRYPTION:

    C[i] = P[i] XOR K[i]

DECRYPTION:

    P[i] = C[i] XOR K[i]

ADVANTAGES:
    Simple.
    Fast in software.
    Small memory requirements.
    Variable-length key.

WEAKNESSES:
    Statistical biases in keystream.
    Weaknesses in key scheduling.
    Vulnerable to practical attacks.
    No authentication or integrity.
    Reusing keystream is dangerous.

SECURITY:
    Broken and deprecated.
    Must not be used in modern applications.

ALTERNATIVES:
    ChaCha20, AES-GCM.
============================================================
```

### 11\. What you must distinguish for the exam

| Term          | Meaning                                                |
| ------------- | ------------------------------------------------------ |
| KSA           | Initializes and shuffles the state array using the key |
| PRGA          | Generates pseudorandom keystream bytes                 |
| S[256]        | Internal permutation of 256 values                     |
| XOR           | Combines plaintext and keystream                       |
| Stream cipher | Encrypts data byte by byte                             |
| Symmetric     | Same secret key is used by both parties                |

The most important thing: RC4 consists of two stages: KSA prepares the internal state using the key, and PRGA generates the keystream. The plaintext is then XORed with that keystream to produce ciphertext.
